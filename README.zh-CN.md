# 文献表整理

一个可复用的 Codex 技能，用来整理带有“论文主表 + 字段说明页”结构的文献表，并为每篇论文建立本地证据链。

这个技能适合这样的工作流：用户维护一张论文表，不希望只是一次性填表，而是希望把分类依据、原文来源、本地证据文件和最终表格结果一起沉淀下来，方便后续复查、协作和迭代。

## 这个技能解决什么问题

很多文献表在整理完成后，分类逻辑只留在整理者脑子里，表格里只剩结果，没有证据来源，也很难继续复用。

这个技能会把整理过程变成一个可追溯工作流：

- 识别论文主表和字段说明页
- 检索论文全文或可信网页来源
- 为每篇论文保留本地原文资产
- 生成逐篇证据 Markdown
- 把结果和路径回写到工作簿
- 在需要时预览并同步回飞书

最终得到的不只是“填好的表”，而是一套可复查、可交接、可继续维护的文献整理结果。

## 支持的输入

支持两种入口：

1. 本地 `xlsx` 工作簿
2. 飞书电子表格链接

## 期望的工作簿结构

同一个工作簿里需要有两类工作表：

1. 论文主表
2. 字段说明页

论文主表至少要有：

- `论文全名`

可选列包括：

- `论文链接`
- `摘要`

字段说明页用于告诉技能“后面的分类列到底是什么意思、应该怎么填”。  
它不是靠工作表名字强绑定，而是靠语义列识别，通常需要能映射出这些表头语义：

- `字段`
- `建议填写方式`
- `推荐取值/说明`

## 核心流程

1. 识别输入来源
2. 检测工作簿结构
3. 确认论文主表
4. 确认字段说明页
5. 准备本地可编辑工作簿
6. 抓取论文来源
7. 生成本地证据文件
8. 回写工作簿
9. 预览飞书同步
10. 仅在明确确认后同步回飞书

## 证据链模型

这个技能会优先为每篇论文保留本地原文资产：

- 如果能下载 PDF，就保留 `paper.pdf`
- 如果只有网页预览，就保留 `source.md`

同时还会生成：

- `paper.txt`
  适用于 PDF 文本抽取
- 每篇论文一份证据 Markdown

工作簿中可以自动追加或复用这些列：

- `本地文件路径`
- `证据链路径`
- `核验警告/状态`

## 仓库结构

- `SKILL.md`
  - 面向 Codex 的技能说明
- `agents/openai.yaml`
  - 技能 UI 元数据
- `scripts/`
  - 结构识别、来源抓取、证据生成、工作簿写回、飞书同步等脚本
- `references/`
  - 工作流、字段说明规则、同步规则等参考文档
- `assets/demo/`
  - 内置演示工作簿和说明文件

## 内置 demo

仓库里附带了一个最小演示工作簿：

- `assets/demo/literature-demo.xlsx`

它用于展示：

- 最小论文主表结构
- 字段说明页结构
- 用户自定义分类列
- 证据链相关列

如果需要重新生成 demo，可运行：

```bash
python scripts/create_demo_workbook.py
```

## 关键脚本

- `scripts/detect_workbook_structure.py`
  - 识别候选论文主表和字段说明页
- `scripts/prepare_local_workspace.py`
  - 准备本地工作副本和证据目录，也支持飞书导出
- `scripts/fetch_paper_sources.py`
  - 解析或抓取论文来源
- `scripts/build_evidence_files.py`
  - 生成证据 Markdown 和 PDF 文本抽取文件
- `scripts/update_workbook.py`
  - 按表头名称写回工作簿
- `scripts/feishu_sync.py`
  - 预览或执行飞书同步
- `scripts/quick_validate.py`
  - 校验技能结构并编译脚本

## 设计原则

- 字段说明页是用户定义列的解释基准
- 技能不把某一种研究分类体系硬编码到所有表里
- 证据不足时，优先写警告，而不是假装分类很确定
- 飞书编辑采用“先本地、后同步”的保守流程
- 证据链不是附属产物，而是核心输出之一
